# Contextual compute and the harness

Status: `proposed`. The full argument is in [the Loom note](https://github.com/siliconcordat/loom/blob/main/docs/08-contextual-compute.md). This file states only what Layer 4 owns. It does not change the approval gate, the memory log, or the zone router.

The harness is where a person steers, and where the open parameter set is already in force when a task starts. The cloud model does not decide the context inside the task. The ancillary hub did that earlier.

A person can send a steer while work is in progress. The note arrives at the next gap between steps. Cancelling the turn is a separate gesture.

The shared record has two sides. Merge folds the person's changes into the model side. Rebase onto the model replays the person's side on top of the model side. Rebase onto the person replays the model side on top of the person's side. Text moves only when one of those is asked for.

Focus, locks, and a small set of knobs are harness state. They are not edits to frontier weights. Focus, attention lock, future bias, and scrubbing a step come from Spaceship IDE by Chuanqi Sun. Here they are a session queue, not realtime token steering. https://github.com/chuanqisun/spaceship
